## 一、背景与问题

当前 `zephyr17/hermes_agent` 空间存在三个核心问题，本方案逐一解决：

| # | 问题 | 根因 | 解决方案 |
|---|------|------|----------|
| 1 | Hermes 数据每次重置 | `/root/hermes-data` 不在 ModelScope 持久化路径 `/mnt/workspace` 内 | 所有数据软链接到 `/mnt/workspace/zephyr/` |
| 2 | keepalive.yml 每天强制重建容器 | 脚本无条件 `POST /deploy` | 修复为先 GET 状态，仅 Stopped 时才 deploy |
| 3 | Hermes Gateway 崩溃循环 | 以 root 运行，官方拒绝 root 启动 | 创建 `hermes` 非 root 用户运行 |

当前镜像为纯转发镜像，供应链不可审计：
```dockerfile
FROM ghcr.io/comedy1024/hermes-agent-desktop:latest  # 闭源，只有 5 行
EXPOSE 7860 3199 8642
VOLUME ["/opt/data"]  # 不是 ModelScope 持久化路径
```

## 五、端口分配表

> 魔搭 Docker Space 的 8080 端口被平台占用，所有内部端口已修正。

| 服务 | 内部端口 | 绑定地址 | Nginx 路由 | 对外 |
|---|---|---|---|---|
| Nginx | 7860 | 0.0.0.0 | — | ✅ 唯一公网入口 |
| noVNC | 6080 | 127.0.0.1 | /desktop/ | 通过 Nginx |
| llama.cpp server | 8081 | 127.0.0.1 | 不对外 | ❌ 仅 loopback |
| Open WebUI | 8082 | 127.0.0.1 | /chat/ | 通过 Nginx |
| Hermes Gateway | 8642 | 127.0.0.1 | **不进 Nginx** | ❌ 仅 loopback |
| Hermes Studio | 8648 | 127.0.0.1 | /hermes/ | 通过 Nginx |
| Flowise（后续） | 8083 | 127.0.0.1 | /flow/（后续） | 通过 Nginx |

**安全规则**：
- 所有内部服务一律绑 `127.0.0.1`，只有 Nginx 绑 `0.0.0.0:7860`
- docker-compose 中用 `expose` 替代 `ports` 做双保险
- Hermes Gateway API 不进 Nginx 路由表，Hermes Studio 和 Open WebUI 走 `127.0.0.1:8642` loopback 直连

## 六、Nginx 路由设计

```
https://modelscope.cn/studios/zephyr17/hermes_agent/
         │
    Nginx :7860 (Basic Auth 强制)
         │
    ┌────┼────────┬──────────┐
    │    │        │          │
    ▼    ▼        ▼          
/desktop/  /hermes/  /chat/   
  │         │         │        
  noVNC   Hermes    Open     
  桌面    Studio    WebUI   
              │
         Hermes Agent
         (Gateway :8642)
         ← 127.0.0.1 直连
           不经 Nginx
```

| 路径 | 服务 | 内部端口 | 认证 |
|---|---|---|---|
| `/desktop/` | noVNC KDE 桌面 | 6080 | Basic Auth + VNC 密码（双因素） |
| `/hermes/` | Hermes Studio | 8648 | Basic Auth |
| `/chat/` | Open WebUI | 8082 | Basic Auth |
| `/flow/` | Flowise（后续启用） | 8083 | Basic Auth + Flowise 账密 |
| `/api/` | **不进 Nginx** | 8642 | 仅 127.0.0.1 可达，Nginx return 404 |

> 每个服务的子路径（base_path）、WebSocket、静态资源需要分别配置，不能简单写几行 `proxy_pass`。这是本方案最复杂的工程点之一。

## 七、持久化与备份策略

### 7.1 持久化目录结构

```
/mnt/workspace/zephyr/
├── hermes/              # Hermes Agent 数据 (config/sessions/memories/skills)
├── hermes-studio/       # Hermes Studio 数据库与配置
├── open-webui/          # Open WebUI 数据库
├── models/              # GGUF 模型文件 (不备份到 OneDrive)
├── desktop/             # 桌面重要文件
├── projects/            # 项目代码
├── rclone/              # rclone 配置 (chmod 600)
└── backups/             # 本地快照
    ├── hourly/
    ├── daily/
    └── manual/
```

### 7.2 软链接映射

程序看到的路径 → 实际持久化路径：

```
/root/hermes-data          → /mnt/workspace/zephyr/hermes
/root/.hermes-web-ui       → /mnt/workspace/zephyr/hermes-studio
/app/backend/data          → /mnt/workspace/zephyr/open-webui
/root/Desktop              → /mnt/workspace/zephyr/desktop
```

### 7.3 启动时自动恢复逻辑

```
容器启动
   │
   ├── 1. 检查 /mnt/workspace/zephyr/hermes/config.yaml 是否存在
   │
   ├── [存在] → 软链接到程序期望路径 → 启动服务
   │
   └── [不存在] → 首次初始化：
         ├── 从镜像内置种子配置拷贝到 /mnt/workspace/zephyr/
         ├── 生成默认 config.yaml / .env
         ├── 创建 hermes 用户目录结构
         └── 启动服务
```

**无论 ModelScope 重建多少次容器，只要 `/mnt/workspace` 还在，所有配置和数据都会自动恢复。**

### 7.4 OneDrive 加密备份

| 数据类型 | /mnt/workspace | OneDrive 加密备份 |
|---|---|---|
| Hermes 配置/记忆/会话 | ✅ | ✅ |
| Hermes Studio 数据库 | ✅ | ✅ |
| Open WebUI 数据库 | ✅ | ✅ |
| 桌面重要文件 | ✅ | ✅ |
| API Keys | ✅ | ✅（crypt 加密后） |
| 模型文件 (GGUF) | ✅ | ❌（太大，可重新下载） |
| 代码仓库 | ✅ | ✅ |

**备份流程**：
```
每日 03:00 执行：
  /mnt/workspace/zephyr/
      ↓ tar + zstd 压缩
  zephyr-YYYY-MM-DD.tar.zst
      ↓ rclone crypt 加密 (XSalsa20+Poly1305)
  OneDrive Personal /zephyr-backups/
      ↓ rclone copy（不删除远端文件）

保留策略：
  - 本地 backups/：最近 7 天
  - OneDrive：最近 30 天
```

> **关键提醒**：
> - OneDrive 不走 WebDAV（微软已不正式支持），走 rclone 的 OneDrive OAuth 后端
> - 备份用 `rclone copy`（不删远端文件）而非 `rclone sync`（可能删数据）

### 8.5 Dockerfile 模型层

```dockerfile
# Stage 3.5: ModelScope SDK + 模型下载
RUN pip install modelscope
ENV MODELSCOPE_CACHE=/mnt/workspace/zephyr/models

ARG PRELOAD_QWEN3_8B=1

      modelscope download --model Qwen/Qwen3-8B-GGUF; \
    fi
```

## 九、安全加固方案

### 9.1 三道门认证

```
第一层：ModelScope 平台登录（Private 可见性）
    ↓ 只有登录你账号的人才能看到 Studio URL
第二层：Nginx Basic Auth（强制，bcrypt 加密）
    ↓ 访问任何路径前需输入用户名密码
第三层：各应用自身认证
    ├── Hermes Studio Token
    ├── Open WebUI 管理员密码
    ├── VNC 密码（≥8 位，字母+数字）
    └── Hermes AUTH_TOKEN
```

### 9.2 安全配置清单

| # | 加固项 | 实现方式 |
|---|---|---|
| 1 | Nginx 安全 Headers + 限流 | `server_tokens off` + 安全响应头 + `limit_req` 10r/s |
| 2 | Basic Auth 强制（所有对外路由） | `auth_basic` + `htpasswd -bcB`（bcrypt） |
| 3 | /api/ 不进 Nginx 路由表 | `location /api/ { return 404; }`（不用 403） |
| 4 | TigerVNC 密码强制 | `-PasswordFile` + `-SecurityTypes VncAuth` + `-localhost` |
| 5 | rclone.conf 运行时生成 | 不进镜像层，entrypoint 从环境变量生成，`chmod 600` |
| 6 | Trivy 镜像漏洞扫描 | GitHub Actions CI，`--severity HIGH,CRITICAL --exit-code 1` |
| 7 | entrypoint 安全校验 | 符号链接 `realpath` 校验 + 种子配置 `sha256sum` 校验 + 权限检查 |
| 8 | Dockerfile 安全构建 | `--no-install-recommends` + 构建末尾 `apt upgrade` + binary checksum 校验 + 非 root 用户 |
| 9 | 镜像层零密钥 | `.env.example` 只放占位符，真实密钥走 ModelScope Secrets |
| 10 | keepalive.yml 修复 | 先 GET 状态，仅 Stopped 才 deploy，3 次重试 + 失败告警 |

### 9.3 密钥清单（全部走 ModelScope Secrets 注入）

| 密钥 | 用途 |
|---|---|
| `PORTAL_USER` / `PORTAL_PASSWORD` | Nginx Basic Auth |
| `VNC_PASSWORD` | TigerVNC 密码（≥8 位字母+数字） |
| `ONEDRIVE_TOKEN` | rclone OneDrive OAuth |
| `ONEDRIVE_DRIVE_ID` | OneDrive Drive ID |
| `RCLONE_CRYPT_PASSWORD` | 备份加密密码 |
| `RCLONE_CRYPT_PASSWORD2` | 备份加密盐 |
| `HERMES_API_KEY` | Hermes 认证 |
| `MODELSCOPE_API_KEY` | 模型 API 调用（ms-xxx） |

### 9.4 keepalive.yml 修复逻辑

```yaml
# 修复前（问题）：无条件 POST deploy = 每天强制重建容器
# 修复后：先 GET 状态，仅当 Stopped 时才 deploy，3 次重试 + 告警

name: Keepalive
on:
  schedule:
    - cron: '0 */6 * * *'   # 每 6 小时检查

jobs:
  keepalive:
    steps:
      - name: Check space status
        # GET /status → 如果 Running 则什么都不做
      
      - name: Deploy only if stopped
        if: steps.status.outputs.state == 'Stopped'
        # POST /deploy，最多重试 3 次，失败则告警
```

### 9.5 待修复的安全遗留问题

| 级别 | 问题 | 修复方式 |
|---|---|---|
| **中风险** | `verify_seed()` 函数已定义但 `main()` 未调用 | 在 `main()` 里加入种子配置校验调用 |
| 低风险 | `generate_rclone_config()` 缺前置校验 | 开头校验所有必需 Secret 是否存在 |
| 低风险 | keepalive.yml status 检查无错误处理 | STATE 为空/"null" 时加 `::error::` 分支 |
| 低风险 | portal.conf `/health` 的 `add_header` 顺序 | Content-Type 移到 `return` 之前 |
| 低风险 | keepalive.yml Secret 直接嵌入 shell | 改用 `env:` 传递 |

## 十四、架构风险与对策

| 风险 | 级别 | 对策 |
|---|---|---|
| 单容器多服务 | 🟡 | ModelScope 限制只能单容器，用 Supervisord 管理进程，做好健康检查 |
| Nginx 子路径部署各 WebUI 兼容性不同 | 🟠 | 逐个配置 base_path / rewrite / WebSocket headers |
| Hermes root 崩溃 | 🔴 | 创建 hermes 用户，用 gosu 降权运行 |
| ModelScope 构建超时 | 🟡 | 优化 Dockerfile 层缓存，大依赖单独一层 |
| rclone OneDrive Token 过期 | 🟡 | rclone 配置自动刷新，定期检查 |
| 镜像体积过大 | 🟡 | 多阶段构建，清理 apt 缓存，--no-install-recommends |
| CPU 推理速度慢 | 🟡 | 日常对话够用（5-8 token/s），复杂任务走 API |
| Flowise 默认无认证 | 🟡 | 后续启用时必须配 Basic Auth + 环境变量注入账密 |

## 十五、后续升级路径

| 场景 | 升级方式 |
|---|---|
| 加 GPU 提升本地推理速度 | 申请魔搭免费 xGPU → llama.cpp 重新编译 GPU 版 → 本地模型可升级 14B/32B |
| 启用 Flowise | 设 `ENABLE_FLOWISE=1` → Nginx 加 `/flow/` 路由 → 配 Flowise 账密 |
| 加更多本地模型 | `modelscope download --model Qwen/Qwen3-xxx-GGUF` → 修改 llama.cpp 启动参数 |
| 加 AnythingLLM（RAG） | 设 `ENABLE_ANYTHINGLLM=1` → Nginx 加 `/rag/` 路由 |
| OneDrive 空间不足 | 升级到 M365 1TB，或改用其他云盘后端 |

## 附录：Secrets 配置清单（ModelScope 后台填写）

在 ModelScope 空间后台 → Settings → Secrets 中添加以下所有密钥：

```
# Portal 认证
PORTAL_USER=admin
PORTAL_PASSWORD=<你的强密码>

# VNC 桌面
VNC_PASSWORD=<≥8位含字母和数字的密码>

# OneDrive 备份
ONEDRIVE_TOKEN=<rclone 生成的 OAuth Token JSON>
ONEDRIVE_DRIVE_ID=<OneDrive Drive ID>
RCLONE_CRYPT_PASSWORD=<加密密码>
RCLONE_CRYPT_PASSWORD2=<加密盐>

# Hermes
HERMES_API_KEY=<Hermes 认证 Token>

# ModelScope API
MODELSCOPE_API_KEY=ms-xxxxxxxxxxxxxxxx

# ModelScope 平台（GitHub Actions 用）
MODELSCOPE_TOKEN=<魔搭 SDK Token>
SPACE_ID=<空间 ID>
ALERT_WEBHOOK=<告警 webhook，可选>
```

> 所有密钥不写入 Dockerfile，不写入 Git，全部通过 ModelScope Secrets 运行时环境变量注入。镜像层零密钥。
