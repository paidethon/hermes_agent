# ADR 0005：关闭 Xtigervnc 黑名单（单用户、单源地址架构）

日期：2026-09-15 · 状态：已实施

## 背景

所有浏览器到桌面的连接都经 websockify 中转，源地址恒为 `127.0.0.1`。
TigerVNC 的黑名单机制按**源地址**记失败次数：几次错误密码后，`127.0.0.1`
整体被拉黑（默认阈值 5 次、时长指数递增），此后**正确密码也被拒**——
安全协商直接回类型 0 + `Too many security failures`，noVNC 呈现为
「无法连接到服务器」，且持续约 2 小时（2026-09-15 实测复现）。

## 决策

`render_supervisor` 的 Xtigervnc 命令行加 `-BlacklistThreshold=0`（禁用黑名单）。

理由：本部署为单用户、单源地址；黑名单要么不起作用（密码正确）要么自伤
（任何人输错几次 → 所有连接被锁）。VNC 密码本身仍是门禁；平台侧另有
Authelia 会话与魔搭登录两道门。

## 后果与回退

- 清除已生效黑名单 = 重部署（VNC 进程重启即重置，黑名单在内存中）。
- 若未来引入多用户/多源地址，重新评估阈值（改回默认或调成有限值）。
